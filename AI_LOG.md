# Лог работы с AI

ТЗ требует использовать AI-инструменты и не удалять лог. Здесь описано, как шла работа с Claude (Anthropic): что просили, что получили, что проверили.

## 1. Постановка

Дал Claude PDF с тестовым заданием и попросил выполнить его. Из ТЗ выделили жёсткие ограничения: запуск строго `npm install` и `npm start`, порт 3000 через `PORT`, никаких внешних зависимостей, админка `/admin` без авторизации, публичный репозиторий.

## 2. Решения, принятые на старте

2.1. Хранилище: JSON-файл
Решение: данные хранятся в data/db.json, а не в SQLite.
Почему: нативные модули (better-sqlite3) могут не собраться на машине проверяющего, а встроенный node:sqlite есть только в Node 22+. Требование ТЗ «решения, которые не запускаются, не оцениваются» важнее удобства СУБД.
Цена решения: при большом объёме данных JSON не масштабируется, тогда нужна настоящая СУБД.
2.2. Бэкенд: Express
Решение: единственная зависимость проекта.
Почему: привычный стек, минимум настройки, меньше точек отказа при npm install.
2.3. Фронтенд: чистый JavaScript без сборки
Решение: обычные файлы в public/, без сборщика и фреймворка.
Почему: не нужен шаг сборки перед запуском, проект стартует двумя командами.
2.4. Что выбрано главным
Решение: конструктор формы, публикация по ссылке, просмотр ответов и аналитика отказов.
Почему: ТЗ называет две проблемы: менеджеры зависят от разработчиков, а причина отказов студентов неизвестна. Решение закрывает обе. Остальное (уведомления, условная логика) оставлено за рамками MVP: в ТЗ сказано, что продуманность важнее количества функций.

## 3. Что реализовано

1. Сервер, API и хранилище.
2. Валидация ответов на сервере по схеме формы.
3. Конструктор формы с живым превью и шаблоном «Стажировка».
4. Публичная форма с автосохранением черновика и прогрессом.
5. Воронка по вопросам: по событиям «открыл форму» и «дошёл до вопроса» считается, где студенты уходят.
6. Таблица ответов, просмотр, удаление, выгрузка в CSV.

## 4. Проверка 

- Написан сквозной тест `test/smoke.js` (`npm test`): 15 проверок ключевого сценария через HTTP, включая серверную валидацию, воронку, CSV, сохранность старых ответов после изменения формы и удаление.
- Первый прогон теста упал на проверке BOM в CSV. Причина была в самом тесте: `fetch().text()` отбрасывает BOM. Тест исправлен на проверку байтов, код сервера не менялся.
- Второй сбой тоже был в тесте: временная папка удалялась, пока сервер ещё сбрасывал данные на диск при остановке. Теперь тест дожидается выхода сервера.
- Интерфейс прогнан в jsdom: список форм, заполнение студентом, отправка, таблица ответов, диалог ответа, аналитика, создание формы по шаблону, добавление вопроса, сохранение, ошибки валидации. JS-ошибок в консоли нет.
- Проверена XSS: ответ с `<b>…</b>` отображается как текст, а не как разметка.
- Запуск проверен «с нуля» в чистой копии без `node_modules`: `npm install`, `npm start`, `http://localhost:3000/admin`.

## 5. Чего не проверял

Не проверял работу в реальных браузерах (только jsdom) и на реальном мобильном устройстве.
