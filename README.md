# Сервис форм отклика

Менеджер сам собирает форму отклика в админке и публикует её по ссылке. Студент открывает ссылку и заполняет форму. Менеджер смотрит ответы и видит, на каком вопросе студенты бросают заполнение.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm start
```

- Админка: http://localhost:3000/admin (без авторизации, как требует ТЗ)
- Публичная форма: `http://localhost:3000/f/<ссылка>`. Ссылку выдаёт админка.
- Порт настраивается переменной окружения: `PORT=8080 npm start`
- При первом запуске создаётся демо-форма, её ссылка печатается в консоль.
- Тесты: `npm test`. Тест сам поднимает сервер на свободном порту с временной базой.

Внешних зависимостей нет: ни API-ключей, ни СУБД, ни облака. Данные лежат в `data/db.json`. Чтобы сбросить всё, остановите сервис и удалите этот файл.

## Что умеет

**Менеджер (админка)**
- Конструктор формы: 10 типов вопросов (короткий и длинный ответ, e-mail, телефон, число, ссылка, дата, выпадающий список, один вариант, несколько вариантов), обязательность, подсказки в полях, порядок, дублирование и удаление вопросов.
- Живой предпросмотр рядом с редактором. Он рисуется тем же кодом, что и настоящая форма, поэтому выглядит так же, как у студента.
- Готовый шаблон «Стажировка», чтобы не начинать с чистого листа.
- Статусы «Черновик» и «Опубликована». Ссылка копируется одной кнопкой.
- Таблица ответов, просмотр одного ответа, удаление, выгрузка в CSV (открывается в русскоязычном Excel).
- Вкладка «Где бросают форму» с воронкой по вопросам.

**Студент**
- Форма по короткой ссылке, работает на телефоне.
- Ошибки показываются у конкретного вопроса, понятным языком.
- Ответы автосохраняются на устройстве, можно закрыть страницу и вернуться. Это прямой ответ на проблему «студенты бросают форму на полпути».
- Индикатор прогресса.

## Главное решение: как найти причину низкой конверсии

В ТЗ сказано, что студенты бросают форму, а причина неизвестна. Одной цифры «конверсия 12%» для менеджера мало, поэтому сервис фиксирует путь по форме. Для каждого визита записывается, до каких вопросов студент дошёл и на каком остановился. На вкладке «Где бросают форму» менеджер видит воронку по вопросам и подсказку вида «чаще всего форму бросают на вопросе X». Дальше он может переформулировать вопрос, сделать его необязательным или перенести в конец.

Что собирается: только анонимный случайный идентификатор визита и номера вопросов. Никаких персональных данных, cookie и сторонних трекеров.

## Технические решения

- **Express без базы данных.** Хранилище — JSON-файл. Нативных модулей нет, поэтому `npm install` не может упасть на сборке. Запись атомарная (временный файл и переименование).
- **Сервер не доверяет клиенту.** Ответы студента проверяются на сервере по схеме формы: обязательность, форматы, допустимые варианты. Клиентская проверка нужна только для удобства.
- **Старые ответы не ломаются.** Идентификаторы вопросов стабильны, в ответе хранится снимок названий. Если менеджер изменил или удалил вопрос, уже полученные ответы остаются читаемыми.
- **Безопасность.** Весь пользовательский текст выводится через `textContent`, XSS невозможен. В CSV экранируются ячейки, которые Excel мог бы выполнить как формулу. Есть простой ограничитель частоты запросов на отправку ответов.
- **Ссылки.** Короткие, без похожих символов (`0/o`, `1/l`), генерируются криптостойким генератором.
- **Фронтенд** на чистом JS без сборки: ничего не нужно собирать перед запуском.

## Структура

```
server.js          API и маршруты (/admin, /f/:slug, /api/...)
lib/db.js          хранилище (JSON-файл)
lib/forms.js       схема формы, валидация ответов
lib/reports.js     аналитика воронки, таблица ответов, CSV
public/            админка, публичная форма, общий рендерер полей (formkit.js)
test/smoke.js      сквозной тест ключевого сценария
AI_LOG.md          лог работы с AI
```

## Что сознательно не вошло в MVP

Авторизация в админке (ТЗ требует доступ без неё), условная логика вопросов, загрузка файлов, уведомления менеджеру о новых откликах, многостраничные формы, A/B-тесты формулировок. Наиболее полезным следующим шагом я считаю уведомления о новых откликах и условную логику.
